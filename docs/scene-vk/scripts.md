# SceneScript in murasaki-scene-vk

Scenes attach JavaScript to object properties (a clock's `text`, a layer's `origin`, a particle system's `rate`) and to whole objects (`init`/`update` that move things about or create layers). The engine runs them with QuickJS-ng (MIT, vendored in `src/scene-vk/third_party/quickjs`, listed in `docs/third-party.md`). The host is `script/scripthost.*`, the JavaScript side `script/prelude.cpp`, and `render/scenescripts.*` connects both to the scene.

## Model

- Every script is an ES module. The scripts of a scene share one runtime (one memory limit) and one realm, a context where the prelude is evaluated once: each script is a module of that realm with a scope of its own (its top-level declarations are its own, as in any module) and names of its own, which its first line imports (the line numbers stay the file's): `thisLayer`, `thisObject`, `thisScene`, `engine` (its timers, audio buffers and `userProperties`), `setTimeout`, `setInterval`, `clearTimeout`, `clearInterval` and `createScriptProperties`. The realm's globals (`input`, `shared`, `localStorage`, `console`, the vector classes, the modules) are the same objects for every script, and so is the object of a scene object: a property one script defines on its `thisLayer` is there for a script that gets the object from `thisScene.getLayer` (the library's icon launchers set `clicked` and `hovered` that way).
- A script that might change what the others see in the realm gets a realm of its own, where its names are globals. The test (`scriptNeedsOwnRealm`) is a best-effort lexical filter over the source, not a parser: a script goes to its own realm when it names `globalThis`, `Reflect`, `setPrototypeOf` or `getPrototypeOf`; calls `eval`, `Function` or a `.constructor(...)`; uses a `prototype` or `__proto__` in any way but borrowing a method in place (`Object.prototype.hasOwnProperty.call(...)`); assigns to a shared global (`Math = `, `shared = `, `console = `), to a member of one (`Math.x = `, `console.log = `) or to one of its own names; deletes from a shared global; reaches into one by a computed name (`Object['assign']`); passes one as the first argument of `Object.assign`, `defineProperty`, `defineProperties`, `freeze`, `seal` or `preventExtensions`; or declares one of its own names itself (`const engine = ...`). A word in a string or a comment is a false alarm, which costs a realm (about 0.3 MiB). What it does not see (an alias of a module's default export that is then changed, say) changes a shared object for the scripts of the same item, nothing else: every realm of a scene belongs to one item, and the sandbox is the process's. Built-ins are not frozen (Workshop scripts extend prototypes; those get a realm of their own). In the library 13 scripts of 10113 (in 12 scenes) get one: 5 assign to `console`, 5 to `shared`, 2 to `thisLayer`, 1 uses `__proto__`. A script cannot import another script's module (`script:<name>`) or names (`__scope/<id>`).
- A script exports `init(value)` (once, after the scene is loaded) and `update(value)` (every frame). For a *property* script `value` is the property's current value and what `update` returns replaces it; for an *object* script `update` returns nothing and changes the scene through `thisLayer`.
- The module may `import` `WEMath`, `WEColor` and `WEVector` (also available as globals). Other imports fail the script.
- `createScriptProperties().addSlider({...}).addCheckbox({...}).finish()` builds the script's own properties; the object's `scriptproperties` in `scene.json` override the defaults, and user-bound ones follow the property store live.
- Scripts run in file order once per frame, only while the scene is drawn (pause stops them). A scene whose scripts have an `update` is drawn every frame; one without costs nothing extra.

## Globals

| Name | What it gives |
|---|---|
| `thisLayer`, `thisObject` | the object the script is attached to (`ILayer`, `IImageLayer`, `ITextLayer`, `IParticleSystem`, `ISoundLayer`): transform, name, visibility, `alpha`, `color`, `size`, `solid`, text properties, effects (`getEffect`), puppet animation layers and bones, particle instance overrides, parents and children. Writes mark the scene dirty. A script may also sit on the values of the object's material (`constantshadervalues` of its base pass: `color`, `alpha`, `brightness`; 2744921335's bars), which it drives as `material.color`, `material.alpha`, `material.brightness` of the layer, multiplied at draw time with the object's own values; and on a light's values (`light.color`, `light.intensity`, ... , formats.md "Lights"). |
| `thisScene` | layers (`getLayer`, `enumerateLayers`, `createLayer` from a model path, an asset handle, a text description (`text`) or an image description (`image`, default the solid layer `models/util/solidlayer.json`, with `name`, `origin`, `angles`, `scale`, `size`, `alpha`, `color`, `brightness`, `visible`, `alignment`, `parallaxDepth`; `type` is not read), `sortLayer`, `destroyLayer`, `getInitialLayerConfig`) and the scene's settings as properties: `bloom*`, `clearcolor`, `camerashake*`, `cameraparallax*`, `fov`, `nearz`, `farz`; camera transforms. |
| `engine` | `runtime`, `frametime`, `timeOfDay`, `canvasSize`, `screenResolution`, `userProperties`, the device queries (`isDesktopDevice`, `isWallpaper`, `isPortrait`, ...), `registerAudioBuffers(16\|32\|64)` (`Float32Array`s `left`, `right`, `average` refreshed every frame from the spectrum), `registerAsset`, `setTimeout` and `setInterval` (on the frame clock; the function they return cancels). |
| `input` | `cursorWorldPosition` (scene units, y up), `cursorScreenPosition` (pixels from the top left of the output), `cursorLeftDown`. |
| `shared`, `localStorage` | `shared` is an object every script of the scene sees; `localStorage` (`get`, `set`, `delete`, `clear`, with `LOCATION_GLOBAL` and `LOCATION_SCREEN`) is shared too and holds JSON values up to 100 KB, kept between runs in a file of the item's own, `<cache>/murasaki/shader-cache/script-storage/<item folder>.json` (the engine's cache directory, the one the sandbox lets it write; written a second after a change, by the next update or user property call, and when the engine ends; a place that cannot be written keeps it for the run, logged once; a file over 1 MiB or that is not storage is kept as `<file>.bad` and the storage starts empty). The 100 KB are counted in UTF-8, as written. `--check` and the development tools do not read or write it. |
| `console` | `log` and `error` (also `warn`, `info`, `debug`) into the engine's log. |
| `Vec2/3/4`, `Mat3`, `Mat4`, `WEMath`, `WEColor`, `WEVector` | the vector and matrix classes with every member of the reference (angles in degrees, matrices column-major, Euler order x, y, z like the scene's own angles) and the modules' helpers; `WEMath.deg2rad` and `rad2deg` are numbers, as documented, and stay callable. |
| `Date`, `Math`, `JSON`, ... | QuickJS's standard library. The clock scripts read the wall time from `Date`. |

An object script may export these event functions besides `init`, `update` and `destroy` (called when the engine ends): `resizeScreen(size)` (when the output size changes; the first frame only records it), `applyUserProperties(changed)` (once after `init` with every property the scene was given, then the ones that change; `engine.userProperties` always holds all of them), `applyGeneralSettings({language})` (the locale as WE writes it, `en-us`, `es-es`), the cursor events `cursorEnter`, `cursorLeave`, `cursorMove`, `cursorDown`, `cursorUp` and `cursorClick` (only for objects marked solid, hit tested on the object's quad), and the media events (see below).

## Sandbox

- No files, no network, no processes: QuickJS's `std`/`os` modules are not linked and `require` does not exist.
- Memory: 96 MiB for what the scripts allocate, over the fixed cost of the realm and of each script's scope (reserved as 384 and 16 KiB; measured about 320 and 7 KiB resident). A scene with 1000 scripts takes about 13 MiB where a realm per script took 320 MiB, and loads in a tenth of a second instead of more than one. Time: 1 s for a script's module evaluation and `init`; each script's update has 50 ms of its own per frame, and all the updates of a frame together 250 ms (scripts after that wait for the next frame). All enforced by QuickJS's interrupt handler.
- A script that throws or fails to compile is logged once and disabled; one that runs out of time is stopped only after three frames in a row over budget (one slow frame is forgiven). The others and the scene carry on. The host's natives (`__host`) are closed over by the prelude and not reachable from a script, `shared` has no prototype, console output is cut at 4 KiB a message and 64 KiB a script. `--check` compiles every script and runs its `init` on a copy of the scene (250 ms each) and then three frames of updates: scripts over 128 MiB refuse the scene, a cheapest frame of updates over 50 ms (20 fps, the engine's lowest rate) is named `slow scripts` and one over 200 ms refuses it, and a script stopped in those frames is named `script error`; a script whose init or top level throws a `TypeError` or `ReferenceError` (a name WE does not have either, a layer that is not in the scene) is stopped and named `script error` too, as WE goes on without it. A script that runs out of time or memory in its init, or that uses a browser API a SceneScript cannot have (`fetch`, `XMLHttpRequest`, `WebSocket`, `requestAnimationFrame`) or a video texture, refuses the scene with the script and API named.

## Conventions worth knowing

- Angles: scripts see degrees, the scene stores radians; the bridge converts. Colours are 0..1 vectors.
- A text object is an image layer; assigning `thisLayer.text` re-rasterizes only when the string changed.
- Property scripts on particle fields (`rate`, `count`, `lifetime`, `speed`) set the *instance overrides* of the system, the same place `scene.json` puts them.
- Layers created at run time go on top (or at `sortLayer`'s index) and draw with the scene's normal order afterwards.
- Media: the host follows the session's MPRIS players (docs/design/specs/2026-10-21-media-thumbnail-design.md) and tells the engine the state of the one to show (the one Playing; if several play, the one that became Playing last; none: the last that played). A script that exports `mediaStatusChanged`, `mediaPlaybackChanged`, `mediaPropertiesChanged`, `mediaThumbnailChanged` or `mediaTimelineChanged` hears, after its `init`, the present state (nothing plays: `mediaStatusChanged({enabled: false})` and `mediaPlaybackChanged({state: PLAYBACK_STOPPED})` and no more, as before) and then each change; the timeline is told once a second while the media plays, extrapolated from the last report. The properties, thumbnail and timeline events describe a track and are not sent while nothing plays: sending a thumbnail event without a thumbnail made the widgets that play their intro animation from `mediaThumbnailChanged` (2915841260, 2902406982, 3238423642, 3820433567, 3757825891's media area) show an empty box (an assumption about WE, not checked against it). `subTitle` and `contentType` are empty (MPRIS has no such field). The colours of `MediaThumbnailEvent` are `Vec3` in 0..1 and an assumption, computed by the engine from the cover (at most 512 px): its opaque pixels are binned in 4 x 4 x 4 colour cells, `primaryColor` is the mean of the fullest cell, `secondaryColor` and `tertiaryColor` those of the next fullest cells at least 0.25 away in RGB from the colours taken (the primary again when there is none), `textColor` black over a primary whose luma is above 0.5 and white under it, and `highContrastColor` the one of the secondary, tertiary and text colours whose luma is farthest from the primary's. A hook that throws is logged and the script carries on.

- Loading a scene evaluates every script's module, in file order, before it runs any `init` (then in file order too): a library script further down the file (3521337568's) defines through `shared` what the inits of earlier objects call.
- A skinned 3D mesh (a model with bones whose object has `animationlayers`) has the animation layers of a puppet: `getAnimationLayerCount`, `getAnimationLayer`, `createAnimationLayer`, `playSingleAnimation`, `destroyAnimationLayer` and the bone queries work on it as on an image layer with a puppet.
- Scripts on a puppet animation layer's `visible`, `rate` or `blend` are bound as the property `alayer.<n>.<field>` of the object, with the animation layer as `thisObject` (the `'addEndedCallback' in thisObject` test of such scripts then holds).
- Scripts on the constants of an effect pass (`constantshadervalues: {alpha: {script, value}}`) are bound as the property `fx:<effect>:<pass>:<constant>` of the object: `init(value)` gets the constant's value and what `update` returns replaces it (a number or a vector).
- Keyframe animations (the editor's timeline, formats.md "Keyframed properties"): `thisLayer.getAnimation(name)` finds one of the object's by its `options.name` (the first without a name), and a property script's `thisObject.getAnimation()` is the one on its own property (`thisObject` is then an object over `thisLayer`). Each has a clock of its own: it plays on the scene clock unless the file starts it paused; `play` runs it on from where it is, and starts a `single` one that has reached its last key again (the widgets `stop()` and `play()` it on every track); `pause` holds it, `stop` holds it at frame 0, `rate` scales it (0 to 100: it does not run backwards; at 0 `isPlaying()` is false), `setFrame` moves it (0 to `frameCount`); `isPlaying()` is false once a `single` one has reached its last key, and a linked track (`options.parent`) follows its parent. The property keeps its keyframes when it also has a script. A script that does not run (it does not load, its init throws, or it is stopped) cannot play what it was given to play: an animation the file starts paused on that script's own property then plays on the scene clock, as without the script, and that is logged.
- `getTransformMatrix()` is the object's world matrix (`.m`, column major, the position in `m[12..14]`); `getTextureAnimation().setFrame(n)` makes the sprite sheet show that frame and hold it.

## Hostile scripts

Besides the memory limit and the time budgets above: the JavaScript stack is limited to 1 MiB (unbounded recursion throws), one script may have 256 layers it made alive, all scripts of a scene 512 together, and over the scene's lifetime they may create 4096 (`thisScene.createLayer` returns null beyond each limit, logged once; a layer that fails to be made costs nothing, and one a script destroys stops counting towards the first two, so a grid that rebuilds itself does not run out; but a destroyed layer is only hidden, not freed, hence the last limit). A description's numbers must be finite and are held to ranges (origin to a million units, scale to ten thousand, size within (0, 65536], alpha 0..1, colour and brightness to 100): what is not is ignored, a text object's string is cut at 8192 characters and its bitmap at 4096 pixels each way, and an mp3 over 64 MiB or with a sample rate outside 8 to 192 kHz is not played. The tests cover a doubling string, a self-scheduling promise, catastrophic regular expressions, a layer flood and a megabyte of text.
